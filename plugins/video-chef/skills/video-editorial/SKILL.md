# Video Editorial

Build the strongest truthful cut in an editable timeline. Story, performance, and clarity come before decorative polish.

## Entry gate

Confirm the locked brief or state remaining assumptions; canonical project and active sequence; source map and selects; target runtime and format; and the user authority to modify or create project files. If the story is materially unresolved, return to `video-story`. If sources are unresolved, use `video-media-intelligence`.

## Workflow

1. Create a source-linked paper edit in `../../assets/EDIT_PLAN.template.md`.
2. Resolve the timebase, sequence dimensions, audio layout, sync, and proxy/full-resolution relationships.
3. Create an isolated project copy or new sequence for the candidate. Record lineage in the decision and change logs.
4. Build the spoken or action spine first. Preserve meaning, performance, and clean transitions.
5. Add alternate cameras, demos, B-roll, room tone, J/L cuts, graphics placeholders, and music only where they have a stated editorial job.
6. Check the whole cut at normal speed. Remove repetition and confusion before compressing pauses that carry meaning.
7. Export a review candidate with version, date, and purpose in its name. Do not label it final without owner approval.

## Editorial rules

- Every cut must have a reason: clarity, emphasis, time, performance, continuity, or intentional disorientation.
- Avoid constant punch-ins, coverage churn, reaction mining, generic kinetic text, or arbitrary speed changes.
- Preserve natural identity and testimony. Do not splice words to create a statement the speaker did not make.
- Keep multicam angle choice subordinate to speaker, eyeline, continuity, and visual information.
- Use temporary graphics and music as clearly labeled placeholders when approval or rights remain open.
- When a technical defect conflicts with the strongest performance, preserve both the preferred select and best technical alternate for owner review.
